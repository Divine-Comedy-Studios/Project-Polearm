A fast-paced action game might appear straightforward on the surface. Characters move, attack and reacts parties react to incoming threats. But behind a truly engaging action game lies a complex system of interconnected systems. How movement, combat, enemy behavior, physics and even sound and animation must work together, yet how does such a huge amount of interaction remain architecturally clean? Project Polearm is a demo for a Hack-and-Slash video game, developed for the 2026 Swiss Matura project season by Rodin Arslan and Zhile Zhu of the class G4g at the Kantonsschule Baden. This _Technical Documentation_ describes the technical structure, organization, as well as core architectural decisions and systems of the game alongside some insights into the development process.

The project, created using the Godot engine, encompasses roughly ==🔴13400== lines of mostly handwritten code. We sought to learn how to implement features found in hack-and-slash games by doing, but it did not stop at this point. We also sought to do so cleanly and with thought. Not only did we ask ourselves, "What does an action game do and how are they designed?", but we also thought: "How can developers create a highly complex game with countless systems in an interlocking, yet clean and thoughtfully crafted web?"

Project Polearm is a demo for a hack-and-slash game which, on the surface, demonstrates most features expected of one, but also showcases the intersection of data-driven and object-oriented programming, an admixture of design patterns and practices of the game development industry. We utilized our modular architecture and components to create a mobile and dynamic player character, as well as five different enemy types, working together to stop the player, all placed in a series of challenging encounters within a hand-crafted level.

The project was the result of our adventures into the philosophies and paradigmes, modular systems programming, finite state machines, complex entity management and the abstraction of physics for player enjoyment. We reasoned about program architecture and structure, and how they might be cleanly implemented to create engaging gameplay systems. Furthermore, not only the gameplay should be intuitive, we also sought the same for the development experience, with many efforts made to streamline development process, as to be able to develop, test and iterate with maximal efficiency.

As this document aims to highlight the technical development of Project Polearm, please consult the main accompanying report for information about the game design and research of this Project.
